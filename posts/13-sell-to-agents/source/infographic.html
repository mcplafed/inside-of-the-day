Inside of the Day — Accepting agent payments

Are you ready to accept payments from AI agents?

The question is no longer whether agents can pay. It is whether your checkout can accept them safely.

1Publish a machine-readable offerOFFER LAYER
Give the agent a truthful product, price and eligibility record.
Exampleschema.org Offer — price, availability and return-policy vocabulary; not a transaction API
Exampledevelopers.openai.com Product Feed — is_eligible_search / is_eligible_checkout
GuardrailDiscoverable is not purchasable. Keep checkout eligibility explicit.
2Open an agent checkout APISESSION LAYER
Let an authenticated agent build, update and complete a bounded checkout session.
Exampleagenticcommerce.dev ACP Agentic Checkout API — checkout_sessions lifecycle, idempotency keys; beta
Exampleucp.dev UCP capability model — OAuth identity linking; an alternate, early vendor-led path
GuardrailA callable endpoint is not authorization. Require an authenticated buyer and explicit intervention when needed.
3Accept a bounded payment mandateAUTHORIZATION LAYER
Charge only what the buyer authorized — then return an order outcome an agent can act on.
Exampleap2-protocol.org Checkout & Payment Mandate — v0.2; signed on a trusted, non-agentic surface
Exampleagenticcommerce.dev ACP Delegate Payment — merchant/session-bound, capped, expiring token; order webhooks
GuardrailAgent-ready is not auto-approve. Keep merchant policy, decline paths and human approval for high-risk orders.

Accepting agent payments is not adding a wallet button.
It is exposing a safe commerce contract:
offer → checkout → authorization → outcome. Current protocols are vendor-led and early: ACP is beta; AP2 is v0.2; UCP has no published maturity label. Use this as an implementation map, not a claim of universal infrastructure.

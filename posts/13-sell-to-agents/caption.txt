I stopped asking whether agents can pay. I started mapping what a merchant must implement to accept one safely.

Are you ready to accept payments from AI agents? Not whether the agent can pay - whether your checkout can accept it safely.

An agent cannot use a normal browser checkout reliably. It needs an explicit machine path: offer, authorization, recoverable outcome.

1. Publish a machine-readable offer. Offer data, live price and currency, availability, shipping, tax and returns, plus checkout eligibility. Schema.org Offer covers price, availability and returns - a vocabulary, not a transaction API. OpenAI's product feed spec adds is_eligible_search and is_eligible_checkout. Discoverable is not purchasable.

2. Open an agent checkout API. A bounded checkout session an authenticated agent can create, update, complete or cancel, with exact price, tax and terms answers and retry-safe idempotency. Agentic Commerce Protocol's Agentic Checkout API does this, with idempotency keys; still beta. UCP's capability model with OAuth identity linking is an early alternate path. A callable endpoint is not authorization: require an authenticated buyer and explicit intervention for 3DS, address or biometric.

3. Accept a bounded payment mandate. Scoped, expiring authorization - amount, currency, merchant and session binding - that you validate, accept or decline, plus machine-readable order status, tracking, refunds and cancellation. AP2 v0.2 uses a Checkout Mandate and a Payment Mandate signed on a trusted, non-agentic surface. ACP's Delegate Payment token is merchant- and session-bound, capped and expiring. Keep decline codes for age, region and high-risk cases, and a human approval boundary.

These protocols are vendor-led and early: ACP is beta, AP2 is v0.2, UCP publishes no maturity label. Treat this as an implementation map, not universal infrastructure.

And agents should not auto-purchase regulated, age-restricted, high-risk, contractual, medical, financial or irreversible goods without appropriate buyer authorization and merchant controls.

Accepting agent payments is not adding a wallet button. It is exposing a safe commerce contract: offer, checkout, authorization, outcome.

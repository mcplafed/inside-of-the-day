Inside of the Day #6 — Prompt caching

Put the stable part first.

Every call resends the same instructions, tools, and docs. Order the prompt so that stable block is cached — and repeats get cheaper and faster.

Cache miss

Full price again — on the whole prefix. One edited byte up top breaks the match.

edited system prompt · reordered tools
a new example · a changed doc → miss
The mechanism

Both providers cache on an exact prefix match.
Stable context first, changing content last — the prefix pays back on every repeat.

This is a harness decision, not a smarter model. Cache reads still cost about 10% of input — not zero. Minimum prefix size, write cost, and cache lifetime vary by model; check current pricing.
